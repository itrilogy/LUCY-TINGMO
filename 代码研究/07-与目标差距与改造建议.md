## 3. 推荐架构：编排层 Orchestrator

在 `AudioRecordingManager` 与 `TranscriptionManager` 之间增加：

```text
┌──────────────────────────────────────────┐
│           TranscriptionOrchestrator       │
│  mode: Batch | SegmentedVAD | NativeStream│
│                                           │
│  - 读 model.max_audio_ms                  │
│  - 收 PCM 帧 / 段事件                     │
│  - 队列 segment jobs                      │
│  - 拼接 final text                        │
│  - 质量检查 / 回退                        │
└──────────────────────────────────────────┘
```

**原则：** 模型只做「短窗转写」；长度与实时性由编排层保证。

## 4. G1 改造：现场录制 + 稳健 batch

### 4.1 强制分片（P0）

伪代码：

```rust
fn transcribe_long(audio: &[f32], max_ms: u64) -> String {
    let max_samples = (16000 * max_ms / 1000) as usize;
    if audio.len() <= max_samples {
        return engine.transcribe(audio);
    }
    // 优先：按 VAD 静音边界切 <= max_samples 的段
    // 回退：固定窗 + overlap（如 1s）
    let mut out = String::new();
    for seg in split_with_vad_or_window(audio, max_samples, overlap) {
        out.push_str(&engine.transcribe(&seg));
    }
    out
}
```

默认：`max_ms = capabilities.max_audio_ms.unwrap_or(30_000)`。

### 4.2 接入点

- `TranscriptionManager::transcribe` 入口统一走 `transcribe_long`  
- CLI `-f`、history retry 自动受益  
- 日志打印：`segments=N, max_ms=...`

### 4.3 用户可见

- 转写中：「第 3/12 段…」  
- 超窗时 toast：已自动分段  

## 5. G2 改造：VAD 实时分段半实时转写

### 5.1 段状态机

```text
Idle --voice--> InSpeech --silence hangover--> SegmentReady
                     │                              │
                     └──────── stop ────────────────┴→ Flush
```

扩展 `SmoothedVad` 或 recorder：

```rust
enum VadSegmentEvent {
    SpeechFrame(&[f32]),
    SegmentEnd { pcm: Vec<f32>, start_ms: u64, end_ms: u64 },
}
```

### 5.2 半实时策略

| 参数 | 建议默认 |
|------|----------|
| min_segment_ms | 800–1500（过短不提转写） |
| max_segment_ms | min(max_audio_ms, 15000–30000) |
| hangover | 沿用 streaming hangover 或可配 |
| 并发 | 单 worker 队列（避免引擎互斥冲突） |

流程：

```text
SegmentEnd → queue job → ASR → emit PartialTranscriptEvent
Stop → flush 当前段 → FinalTranscript
```

### 5.3 与 Native Stream 的关系

| 模式 | 适用 |
|------|------|
| SegmentedVAD | **任意** batch 模型（SenseVoice/Qwen3…）— **满足 G2 主力** |
| NativeStream | 仅 supports_streaming；适合真·token 级预览 |
| 可选 | Stream 预览 + 最终仍 Segmented/Batch 校准 |

### 5.4 设置项建议

```text
transcription_mode:
  - end_of_utterance   # 现有：录完再转（+ 自动分片）
  - vad_segmented      # G2：边录边按段转
  - native_stream      # 模型原生 stream（若支持）

vad_enabled: bool      # 保留；segmented 模式强制需要 VAD
```

## 6. 质量守卫（防再出现「30 分钟 → 1 千字乱码」）

| 检查 | 动作 |
|------|------|
| audio_s > max_audio_s 且未分片 | 拒绝整段 / 自动分片 |
| 输出 chars / audio_s < 阈值（中文约 < 0.5 字/秒可调） | 警告 + 建议重试分片 |
| 单段 ASR 失败 | 跳过或降低质量重试，不丢整场 |
| stream finalize 超时 | cancel + batch/segment 兜底 |

## 7. 实施分期

### Phase 0（1–2 天）— 止血

- [ ] `transcribe` 内按 30s（或 capability）分片拼接  
- [ ] WARN 上浮到用户 / 日志结构化  
- [ ] 用本机 `handy-1785291861.wav` 回归  

### Phase 1（3–5 天）— G2 MVP

- [ ] VAD 段事件  
- [ ] 段队列 + 单线程 ASR  
- [ ] Partial 文本事件 + overlay/设置页展示  
- [ ] 设置开关 `vad_segmented`  

### Phase 2 — 打磨

- [ ] 段间重叠/上下文 prompt（Whisper initial_prompt）  
- [ ] 进度与可取消  
- [ ] 前端文件上传  
- [ ] 流式最终结果与分片结果比对兜底  

## 8. 测试计划

| 用例 | 期望 |
|------|------|
| 2s 短句 | 与现网一致 |
| 45s 连续说 | 自动 2 段，语义完整 |
| 本机 1808s WAV + SenseVoice | 无超窗整段；字数数量级提升；无「标标标」主导 |
| vad_segmented 现场 3 分钟 | 停顿处陆续出字 |
| 关 VAD + 长录音 | 固定窗分片仍可用 |
| streaming 模型 + finalize 失败 | 回退 batch/segment |

## 9. 非目标（避免范围膨胀）

- 不在本阶段重写全部 UI  
- 不强制替换 SenseVoice；用编排兼容所有模型  
- 不做云端 ASR（保持本地）  

## 10. 成功标准

1. **G1**：任意已支持模型，现场录 30 分钟，文本可读、主题完整（允许少量识别错）。  
2. **G2**：开启分段模式时，说话停顿后数秒内出现段文本，停止后与累计文本一致。  
3. **G3**：同一 `handy-1785291861.wav` 复跑不再出现「仅 1.5k 乱码」级失败；日志无 unhandled 超窗整段 WARN（或仅在未分片 debug 路径出现）。
