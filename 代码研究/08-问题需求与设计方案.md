## 1. 当前问题（统一描述）

### 1.1 一句话

**现场能录很久，但「整段一次送入 ASR」在 SenseVoice 等短窗模型上会严重退化；现有 VAD 只去静音，不能按段半实时出字。**

### 1.2 问题清单（用户可感知）

| ID | 问题 | 用户感知 | 证据 / 机制 |
|----|------|----------|-------------|
| **P1** | 长录音转写内容大幅缩减 / 乱码 | 讲了十几～三十分钟，只出几百～一千多字，且重复乱码（如「标标标」） | 安装版：1808s WAV 完整；`beyond the ~30 s window`；结果约 518 字 |
| **P2** | 长录音转写质量崩坏 | 主题依稀可辨但后部糊、叠字、不可用于纪要 | 同引擎 WARN：超训练窗 + 内存二次方增长风险 |
| **P3** | 无「边说边出字（分段）」 | 必须说完再等整段推理（30 分钟音频可能再等数分钟） | 应用层无 segment job；仅部分模型有 native stream |
| **P4** | VAD 语义与预期不符 | 以为开 VAD = 智能分段；实际只是丢静音再整段转 | `VadPolicy` 帧门控，非 `SegmentEnd → ASR` |
| **P5** | 管理/链路偏重、难控 | 多 Manager + 双引擎 + stream/batch 分叉，长音频策略无处安放 | `actions` / `TranscriptionManager` / `StreamRouter` 交织 |
| **P6** | 失败不透明 | 用户看不到「超 30s 应分片」；只能感知结果变差 | WARN 仅在日志；设置 UI 未展示 `max_audio` |

### 1.3 问题因果链

```text
用户长时间现场讲话
    → 录音链路正常（16k mono WAV 完整落盘）
    → VAD 去掉静音帧（可选），仍得到超长 speech PCM
    → session.run(整段) / transcribe(整段)
    → 模型 max 窗约 30s（SenseVoice）被远超
    → 精度崩溃 + 有效文本变短/乱码
    → 用户结论：「长录音转义出错」
```

**不是**（本案例主因）：麦克风没录上、剪贴板截断、LLM 后处理删字（history 中长录 `post_process_requested=0`）。

### 1.4 与「Handy 现产品定位」的错位

| Handy 默认假设 | 你的实际场景 |
|----------------|--------------|
| 短 dictation（数秒～几十秒） | 现场长讲（十几～三十分钟+） |
| 录完一次粘贴进输入框 | 需要稳健长文本 + 可选半实时进度 |
| VAD = 省算力/去静音 | VAD = 分段边界 + 逐段转写 |

## 2. 需求（统一描述）

### 2.1 核心需求（Must）

| ID | 需求 | 验收口径 |
|----|------|----------|
| **R-A** | **现场录制**：快捷键开始/结束（或 PTT），采集麦克风 | 与现网一致可录、可存 WAV |
| **R-B** | **选定模型转写**：用户选中的本地 ASR 模型对录制音频做转写 | 短音频质量不低于现网；长音频可读、主题完整 |
| **R-C** | **长音频正确性**：无论用户录多久，不得因「超模型窗」导致整场崩溃 | 同 30min WAV 复跑：无整段超窗 WARN（或仅 debug）；字数/可读性显著提升 |
| **R-D** | **可选 VAD 分段半实时**：开启后，按语音停顿切段，**逐段**转写并追加文本 | 停顿后数秒内出现段文本；停止后 cumulative = final |
| **R-E** | **可理解、可配置**：用户知道当前模式、模型限制、进度 | 设置中可见模式与 max 窗；转写中有进度 |

### 2.2 次要需求（Should）

| ID | 需求 |
|----|------|
| **R-F** | 文件路径：对已有 WAV / 历史条目重试时，享受同一分片逻辑 |
| **R-G** | 质量守卫：输出过短/失败可提示重试或自动降级策略 |
| **R-H** | 尽量少改「短 dictation」路径的延迟与体验 |

### 2.3 非需求（Won't / 本期不做）

- 云端 ASR / 多说话人 diarization  
- 完整会议系统（视频、屏幕共享）  
- 重写全部设置 UI 视觉  
- 强制废弃 Handy 托盘/快捷键范式（可作为可选交互叠加，见第 6 节）  

### 2.4 用户故事

1. **作为** 现场听会/培训记录者，**我希望** 按快捷键录完整场，结束后在 overlay 看到完整可读文稿并一键复制，**以便** 不用再人工听回放、也不会误贴到错误窗口。  
2. **作为** 同上用户，**我希望** 可选打开「边说边转」后，讲话停顿处在 overlay 陆续出字，**以便** 确认已录上且不用干等 30 分钟（该模式默认关闭）。  
3. **作为** 开发/运维，**我希望** 转写策略集中在一处编排，**以便** 换模型、改交互时不必改五处 Manager。

## 4. 设计目标与非目标

### 4.1 设计目标

1. **正确性优先于「一次推理」**：模型只吃 ≤ max_audio 的块。  
2. **编排与引擎解耦**：分片 / 半实时属于编排层，不属于某个具体模型实现。  
3. **管理形态可轻可重**：提供「轻量会话 Session」主路径；现有 Manager 可降为适配器。  
4. **交互可渐进**：默认仍兼容 Handy 快捷键；可叠加「录制面板」交互，不必二选一推倒重来。  
5. **用证据回归**：以本机 `handy-1785291861.wav` 为黄金用例。  

### 4.2 非目标

- 一次 PR 完成所有模式与全部 UI 改版。  
- 为每个模型手写特殊分片逻辑（统一策略 + 读 capability）。

## 5. 方案选项：管理形态

「管理形态」指：**谁拥有录音生命周期、谁排队 ASR、谁拼文本**。

### 选项 M0 · 维持多 Manager（现状）

```text
Coordinator → Action → AudioManager + TranscriptionManager + HistoryManager
```

| 优点 | 缺点 |
|------|------|
| 零结构成本 | 长音频策略只能塞进 `transcribe` 或 `actions`，继续散落 |
| | stream/batch 分叉难统一 |

**结论**：可做 P0 止血补丁，**不适合**作为 G2 终态。

---

### 选项 M1 · 轻量 Session（推荐）

引入单一 **`RecordingSession`**（或 `TranscribeSession`），一次录制 = 一个 Session 对象：

```text
Session {
  id, mode, model_id,
  pcm_or_segments,
  partial_text, final_text,
  state: Idle|Recording|Transcribing|Done|Failed
}
```

| 职责 | 归属 |
|------|------|
| 开停麦、取帧 | 薄封装现有 `AudioRecordingManager` / Recorder |
| 段切分 / 窗切分 / 队列 ASR | **Session 内 Orchestrator** |
| 调模型 | 仅调用 `TranscriptionManager::transcribe_segment` |
| 历史 / 复制 | Session 结束 → History；overlay「复制」→ clipboard（**不**模拟粘贴键） |

| 优点 | 缺点 |
|------|------|
| 状态机清晰；一录一会话 | 需新增类型与生命周期 |
| 易测（可对假 PCM 跑 Session） | 需把 `actions.rs` 变薄 |
| 管理「轻」：业务逻辑不散落 4 个 Manager | |

**「轻量」含义**：不是删掉 Manager，而是 **Manager 变基础设施，Session 变业务中心**——比再叠一层重型微服务式编排更轻。

---

### 选项 M2 · 极简管道（Pipeline-only）

取消概念上的 Session，只做函数式：

```text
record() → Vec<Segment> → map(asr) → join → paste
```

| 优点 | 缺点 |
|------|------|
| 代码最少 | 半实时、取消、进度、UI 事件难挂载 |
| | 与现有异步 Action/Coordinator 难融合 |

**结论**：适合 CLI/批处理；**不适合**桌面半实时。

---

### 选项 M3 · 重型「引擎服务」进程

独立 ASR daemon + IPC。

| 优点 | 缺点 |
|------|------|
| 隔离崩溃 | 对 Handy 体量过重；本期不需要 |

**结论**：否决（本期）。

---

### 管理形态对比

| 维度 | M0 现状 | **M1 Session（荐）** | M2 管道 | M3 守护进程 |
|------|---------|----------------------|---------|-------------|
| 实现成本 | 低 | 中 | 低 | 高 |
| 长音频分片 | 难挂 | 自然 | 易 | 易 |
| 半实时段 | 难 | 自然 | 难 | 可 |
| 可测试性 | 中 | 高 | 高 | 中 |
| 与现码兼容 | 高 | 高（适配） | 中 | 低 |
| 心智负担 | 高（散） | **低（一会话）** | 低但弱 | 高 |

**推荐：M1 轻量 Session。**

## 6. 方案选项：交互形态

### 选项 I0 · 保持「快捷键开停录」

- 开始/结束：Option+Space（toggle）或 PTT  
- **结果：不自动粘贴**（见已拍板 D8）；文稿进 expanded overlay + history，用户点「复制」  
- Overlay：录制中 minimal/电平；结束后/长录/半实时用 **扩大 overlay**  

| 适合 | 不适合 |
|------|--------|
| 控制录制节奏、与现快捷键习惯一致 | 若仍期望「说完即进当前输入框」——本期明确不做 |

---

### 选项 I1 · 扩大 Overlay 会话面板（已选定）

快捷键仍可开停录；**结果与进度统一落在扩大后的现有 overlay**（不新开独立会议窗）：

```text
┌──────────────────────────────────┐
│  ● 录制中 / 转写中  12:34         │
│  模式: 录完再转 | 模型名          │
│  ────────────────────────────    │
│  （滚动文本；分段模式下逐段追加）   │
│  ────────────────────────────    │
│  [停止] [取消] [复制]  （无自动粘贴）│
└──────────────────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 复用 overlay 管线，少窗口 | 需扩展现有 overlay 布局与状态 |
| 长内容可见、主动复制 | 相对「自动粘贴」多一步（产品已接受） |
| 进度/段状态可展示 | |

---

### 选项 I2 · 「会议模式」独立入口

设置或托盘：「开始会议录制」→ 专用窗口，不自动粘贴，只生成文稿。

| 优点 | 缺点 |
|------|------|
| 与 dictation 产品完全分离 | 两套交互；用户要学两种 |

适合未来产品线拆分；**本期可用 I1 覆盖 80%**。

---

### 选项 I3 · 仅文件后处理

只提供「导入 WAV → 转写」，不强调实时。

| 优点 | 缺点 |
|------|------|
| 实现简单 | **不满足** 现场录制主需求 R-A |

可作附加能力，不能当主交互。

---

### 交互形态组合（已拍板）

```text
开/停录           → I0：快捷键（与现网一致）
录制中 / 转写中 / 结果  → I1：扩大 overlay 展示计时、进度、全文
结束后            → 写入 history + WAV；overlay 保留结果
用户动作          → 仅「复制」（及可选「关闭」）；**永不自动粘贴**
分段半实时        → 默认关；开启后同 overlay 内逐段追加文本
```

**Overlay 展示规则（固定）：**

| 条件 | Overlay 行为 |
|------|----------------|
| 任意录音进行中 | 扩大 overlay：计时 + 模式/模型；分段模式显示累计文本 |
| 转写进行中 | 扩大 overlay：进度（段 i/n 或 spinner） |
| 转写完成 | 扩大 overlay：全文 + **[复制]**；不粘贴到焦点应用 |
| 取消 / 失败 | overlay 提示后可关闭；WAV/history 策略见实现 |
| 历史重试 / 文件 | 同扩大 overlay 或设置页结果区，仍不自动粘贴 |

## 7. 推荐方案 R1

### 7.1 一句话

**采用轻量 `RecordingSession` 编排 + 模型短窗分片保证正确性；快捷键只负责开停录；结果与进度一律在扩大 overlay 中展示，用户手动复制；分段半实时默认关闭。**

### 7.2 转写模式（产品三档）

| 模式 ID | 名称 | 行为 | 默认 |
|---------|------|------|------|
| `batch_auto_split` | 录完再转（自动分片） | 停录后按 VAD 边界或固定窗切 ≤ max_audio，顺序 ASR，拼接 | **是（修复 P1）** |
| `vad_segmented` | 分段半实时 | 段结束即 ASR，overlay 追加；停录 flush 尾段 | **关**（用户可选开启） |
| `native_stream` | 模型流式 | 仅 supports_streaming；结束建议与 auto_split 校验（可选） | 模型能力允许时可选，默认不强制 |

### 7.3 相对现状的心智变化

| 点 | 变化 |
|----|------|
| 快捷键 | 仍开停录，**不再**「说完自动进当前输入框」 |
| 取结果 | 扩大 overlay **[复制]** → 用户自行粘贴 |
| 长录音 | 自动分片，无需懂 max_audio |
| 半实时 | 设置里手动打开「分段半实时」 |
| 开发 | Session 状态机 + `transcribe_segment` |

## 8. 架构设计

### 8.1 逻辑结构

```text
                    ┌─────────────────────┐
  快捷键/托盘/CLI → │ TranscriptionCoordinator │  (仍负责防抖/串行)
                    └──────────┬──────────┘
                               │ start/stop/cancel
                    ┌──────────▼──────────┐
                    │  RecordingSession    │  ← 新增，业务中心（轻量）
                    │  mode / state / text │
                    └──────────┬──────────┘
               ┌───────────────┼───────────────┐
               ▼               ▼               ▼
        AudioCapture      Segmenter       AsrRunner
        (现有 Recorder)   (VAD段/固定窗)   (调 TranscriptionManager)
               │               │               │
               └───────────────┴───────────────┘
                               │
                    Events → UI Panel / Overlay
                    Done   → History + Clipboard
```

### 8.2 模块职责

| 模块 | 职责 | 实现提示 |
|------|------|----------|
| `RecordingSession` | 一次录制状态机；持有 mode；汇总 partial/final | 新建 `session.rs` 或 `orchestrator.rs` |
| `Segmenter` | 帧 → `SegmentEnd` 或 停录后 offline 切分 | 扩展 SmoothedVad 或后处理切分 |
| `AsrRunner` | 串行队列跑 `transcribe_segment(pcm)`；取消 | 包一层现有引擎，**禁止**整段超窗 |
| `AudioCapture` | 开停、帧回调 | 复用 `AudioRecordingManager` |
| `TranscriptionManager` | 加载模型、**单段**推理 | 现有 `transcribe` 改为内部只吃安全长度或拆成 `transcribe_raw` + 外部分片 |
| `SessionUi` | 扩大 overlay + 事件 | **扩展现有 overlay**（已拍板，不新开会议窗） |

### 8.3 分片算法（正确性核心）

**在线（vad_segmented）**

```text
on frame:
  vad → Speech: append to current_seg
  vad → SegmentEnd: if len >= min_seg → enqueue ASR(current_seg); clear
on stop:
  flush current_seg if any
  wait queue drain → final_text = join(segments)
```

**离线（batch_auto_split）**

```text
input: full pcm (可已去静音)
1) 优先在静音处切开，使每段 ≤ max_samples
2) 无静音长段 → 固定窗 max_samples，overlap 0.5–1.0s
3) 顺序 ASR，拼接（中文直接相连；西文段间空格策略可配置）
```

**max_samples 来源**

```text
max_ms = model_capability.max_audio_ms
         ?? family_default (SenseVoice: 30000, Whisper: 30000, 未知: 30000)
max_samples = 16000 * max_ms / 1000
```

### 8.4 与现有 Stream 路径关系

| 情况 | 策略 |
|------|------|
| `native_stream` + 模型支持 | 可走现 StreamRouter；**finalize 失败或质量差 → auto_split 兜底** |
| `vad_segmented` | **不**走 native stream；用段队列 |
| `batch_auto_split` | 不走 stream |

避免再出现：`finalize` 半成品挡住完整结果。

### 8.5 状态机（Session）

```text
Idle
  --start--> Recording
  --stop-->  Transcribing (batch) | Flushing (segmented)
  --cancel--> Cancelling → Idle
Recording
  --segment_done--> (仍 Recording，后台 TranscribingSegment)
  --error--> Failed
Transcribing / Flushing
  --all_done--> Done → expanded overlay 展示全文 + [复制]
  --error--> Failed
```

同一时刻 **仅一个** 活跃 Session（与现 Coordinator 单管道一致）。  
**Done 后禁止** 调用现有 `paste` / 模拟键入路径；仅 `clipboard` 写入发生在用户点击「复制」时。

### 8.6 数据与事件

**后端 → 前端事件（建议）**

```typescript
// 概念 API，非最终绑定名
SessionStateEvent { sessionId, state, mode, elapsedMs }
SessionPartialTextEvent { sessionId, segmentIndex, text, cumulative }
SessionProgressEvent { sessionId, doneSegments, totalHint? }
SessionFinalEvent { sessionId, text, audioPath? }
SessionErrorEvent { sessionId, code, message }
```

## 9. 交互设计细则

### 9.1 设置页

新增一组 **「转写模式」**（文案示例）：

| 选项 | 说明 |
|------|------|
| 录完再转（推荐） | 结束后自动按模型能力分段转写，适合任意时长 |
| 边说边转（VAD 分段） | 停顿处逐段出字，适合长讲与确认进度 |
| 模型实时流式 | 仅当模型支持；预览型 |

保留现有：

- `vad_enabled`：在「录完再转」中仍控制是否去静音；在「边说边转」中 **强制开启**（UI 提示）。  
- 模型选择：卡片上增加「最长建议单段：约 30s」类提示（来自 capability）。  

### 9.2 录制中（一律扩大 overlay）

| 模式 | 扩大 Overlay 内容 |
|------|-------------------|
| 录完再转（默认） | 计时、模型名、提示「结束后自动分段转写」；电平可选 |
| 边说边转（用户开启） | 同上 + 滚动 cumulative 文本 + 当前段「转写中…」 |

> 已拍板：**不使用独立会议窗口**；在现有 overlay 上扩展尺寸与文本区。

### 9.3 结束后（不自动粘贴）

1. `final_text` 写入 history + 保存 WAV。  
2. 扩大 overlay 展示全文。  
3. 主按钮：**[复制]**（写入系统剪贴板）。  
4. **禁止**自动 `paste` / 模拟 Cmd+V / 自动打字进焦点应用。  
5. 用户如需贴入某处：自行到目标应用粘贴。  
6. 可选次要操作：关闭 overlay、打开历史（实现阶段定）。  

### 9.4 失败与提示

| 情况 | 提示 |
|------|------|
| 单段失败 | overlay：「第 N 段失败，已跳过/重试」 |
| 全部失败 | 保留 WAV，history 可重试；overlay 错误文案 |
| 模型超窗被分片 | 日志 info；可选首次 overlay 轻提示「已按模型限制自动分段」 |

## 10. 关键决策

| # | 决策 | 理由 |
|---|------|------|
| D1 | 采用 **M1 轻量 Session**，而非继续堆 Manager 或上 daemon | 状态集中、可测、改动可控 |
| D2 | **所有** 长音频默认 `batch_auto_split`，不依赖用户懂 max_audio | 直接修复 P1/P2 |
| D3 | G2 用 **应用层 VAD 段队列**，不绑定 native stream | SenseVoice/Qwen3 等主力模型不支持 streaming |
| D4 | 交互：**快捷键开停 + 扩大 overlay**；不做独立会议窗 I2 | 少窗口、复用现 overlay |
| D5 | `TranscriptionManager` 降为 **单段推理 + 模型加载** | 编排与引擎分离 |
| D6 | 黄金回归：① 安装版 1808s history WAV；② **鑫苑路9号 ≈77min**（`代码研究/fixtures/`） | 有真实失败样本 + 更长会议样例 |
| D7 | 本期不做 M3 / 云端 / 说话人分离 | 控制范围 |
| **D8** | **不自动粘贴**（短文/长文均否）；仅用户点「复制」写剪贴板 | 用户拍板 2026-07-29；避免误贴、长文场景主路径 |
| **D9** | **`vad_segmented` 默认关** | 用户拍板；避免改变默认节奏与算力占用 |
| **D10** | **面板形态 = 扩大现有 overlay**（非独立 BrowserWindow 会议页） | 用户拍板；实现路径清晰 |

## 14. 总结表

| 维度 | 结论 |
|------|------|
| **当前问题** | 长 PCM 整段推理超模型窗 → 内容缩减/乱码；VAD 未做段级半实时；策略散落 |

| **交互形态** | 快捷键开停 + **扩大 overlay**；**不自动粘贴**；半实时默认关 |
| **技术关键** | 编排层分片；模型只跑短段；三档模式 |
