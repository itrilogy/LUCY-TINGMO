> 来源（领域实例，仅作范式提炼，**不绑定烟草业务**）：  
> - `.../标准化管理/ASR转义纠偏提示词.md`  
> - `.../标准化管理/ASR修正标识物清单.md`  
> 提炼日期：2026-07-29  
> 用途：指导 Handy / 通用本地 ASR 工程中的**后处理纠偏**与**词库生长**设计

---

## 1. 问题本质（与领域无关）

长录音 ASR 原始输出常见三类缺陷：

| 缺陷 | 表现 | 仅靠 ASR 模型是否够用 |
|------|------|----------------------|
| **无标点 / 无分段** | 字连成一片 | 部分模型可出标点，多数长录音仍差 |
| **同音/近音误识** | 专名变成日常词 | 需领域词表 + 语境规则 |
| **结构丢失** | 讲次、问答、案例边界消失 | 需任务级后处理，不是词替换 |

领域文档的解法是两层：

1. **提示词流水线（LLM 纠偏）** — 恢复标点、术语、结构  
2. **标识物清单（持久化误识对照表）** — 每次纠偏后**增量入库**，形成生长的知识库  

这与 Handy 现有能力对照：

| 层 | Handy 现状 | 领域范式 |
|----|------------|----------|
| 帧级/段级 ASR | Phase 0/2 分片、VAD 半实时 | 产生 raw 文本 |
| 模糊自定义词 | `custom_words` + Levenshtein/Soundex | 仅英文友好，**不是**权威对照表 |
| Filler 过滤 | `filter_transcription_output` | 对应「删口头禅」 |
| LLM 后处理 | post-process prompts（通用「润色」） | 对应「纠偏提示词」但缺**强制读清单**与**增量回写** |
| 易错词库 | 无独立「误识→正确」知识库 | **标识物清单** |

## 2. 提示词纠偏范式（Prompt Correction Pattern）

### 2.1 架构：三件套

```text
┌─────────────────┐     每次任务强制加载      ┌──────────────────┐
│ 纠偏 System/     │ ◄─────────────────────── │ 标识物清单.md     │
│ User Prompt      │                          │ (权威、可生长)    │
└────────┬────────┘                          └────────▲─────────┘
         │ 输入: ASR raw                              │
         ▼                                            │ 规则七：仅经验证
┌─────────────────┐     输出: 正文 + 附注              │ 的新模式入库
│ LLM 纠偏         │ ─────────────────────────────────┘
└────────┬────────┘
         │
         ▼
   可交付正文 + 【存疑】+ 【新增标识物】
```

**关键原则：**

| # | 原则 | 领域文档对应 | 工程含义 |
|---|------|--------------|----------|
| P1 | **清单优先于提示词内嵌表** | 前置操作 1–2 | 静态 prompt 会过时；运行时注入权威词库 |
| P2 | **先加载知识库再纠偏** | 「必须先读清单，不可跳过」 | Agent/流水线的 hard gate，不是可选 |
| P3 | **任务边界清晰** | 只做纠偏，不编造内容 | system 约束：不补课、不答问、不摘要（除非另开任务） |
| P4 | **规则分层** | 规则一～七 | 标点 / 专名 / 分段 / 口语 / 数字 / 存疑 / 增量 |
| P5 | **输出结构化** | 正文 + 附注 + 新增标识物 | 便于自动解析、回写词库、人工复核 |
| P6 | **示例锚定** | 输入→输出样例 | 稳定格式与纠偏力度 |

### 2.2 提示词模块化模板（通用）

可直接改写成 Handy `post_process_prompts` 或外部 Agent skill：

```markdown
# Role
你是 ASR 后处理纠偏器，不是内容创作器。

# Preconditions（硬门禁）
1. 已加载「标识物清单」全文（权威源，优先于下文任何静态表）
2. 未加载清单则仅使用内嵌冷启动表，并在任务结束创建/更新清单

# Input
- 领域/场景标签（可选）：课程名、会议类型、讲者…
- ASR 原始文本（可能无标点、有误识）

# Rules
1. 标点与分段：按语义恢复；不改变事实内容
2. 专名：清单优先 → 语境推断 → 仍不确定则【存疑】
3. 口语：删填充词；保留必要语气；重复只留最完整一次
4. 数字/编号：统一格式（年份、%、标准号…按领域配置）
5. 禁止编造：无法还原处标记 [存疑：原文为"…"]
6. 增量：新误识模式写入【新增标识物】表，仅「明确验证」可入库

# Output schema
【场景】
（纠偏正文）

【附注】
- 修正说明：…
- 存疑：…
- 新增标识物：
  | ASR误识 | 正确形式 | 类别 |
```

### 2.3 与 Handy LLM 后处理的差距与对齐

| 领域范式 | Handy 现 post-process | 建议对齐 |
|----------|----------------------|----------|
| 强制读标识物清单 | 仅用户 prompt 字符串 | 注入 `custom_glossary` / 文件路径 |
| 纠偏 ≠ 润色改写 | 默认 prompt 偏「clean spelling」 | 增加专用 prompt 模板「ASR 纠偏」 |
| 存疑标记 | 无 | 输出协议支持 `[存疑]` |
| 新增标识物回写 | 无 | 解析附注 → 合并词库 |
| 领域背景（课程表/讲者） | 无 | 可选 `session_context` JSON |

**Handy 落地最小增量（建议 PR 级）：**

1. 内置 prompt：`asr_domain_correct`（上表模板 + `${glossary}` + `${raw}`）  
2. 设置项：绑定 glossary 文件或内置 JSON  
3. 后处理结果可选「仅复制 / 写回 history」，与 Phase 1「不自动粘贴」一致

## 3. 易错词 / 标识物自动增量管理范式

### 3.1 数据模型（通用）

领域清单表头可抽象为：

```text
Marker {
  asr_error: string | string[]   // 一种或多种误识
  correct: string                // 权威正确形式
  category: enum                 // 机构/术语/人名/地名/编号/格式…
  note?: string                  // 消歧说明（何时用全称等）
  source?: string                // 首次发现场景
  confidence: verified | pending // 是否已人工确认
  created_at, updated_at
}
```

**分类（十类可映射为可配置 taxonomy）：**

| 类别抽象 | 领域例子类型 | 通用场景 |
|----------|--------------|----------|
| 机构/体制 | 局、公司、委员会 | 客户组织名 |
| 核心概念 | 标准化、体系 | 产品/业务关键词 |
| 文件与编号 | YC/T、GB/T | 工单号、法规号 |
| 活动专属 | 培训班口号 | 项目代号 |
| 地名/单位 | 省中烟 | 分公司、门店 |
| 人名 | 讲师 | 客户、同事 |
| 专业检测/工艺 | 打叶复烤 | 行业工艺词 |
| 信息/物流等垂直 | 数据元 | 按项目扩展 |
| 格式规范 | 周期、年份、% | 全局格式规则 |

### 3.2 增量闭环（核心范式）

```text
        纠偏任务
            │
            ▼
    ┌───────────────┐
    │ 应用清单纠偏   │
    └───────┬───────┘
            │ 发现新误识
            ▼
    【新增标识物】候选
            │
     ┌──────┴──────┐
     │ 明确验证？   │
     └──────┬──────┘
        是／否
        │    └──→ 附注「待核实」，不入库
        ▼
    合并进清单对应分类
            │
            ▼
    增量更新日志 +1 行
   （日期 / 条数 / 来源场景）
```

**维护规则（可产品化）：**

| 规则 | 说明 |
|------|------|
| **单一权威源** | 清单文件/DB 优先于 prompt 内嵌表 |
| **只增可信** | 存疑不入库；人工确认后再 `pending→verified` |
| **分类归桶** | 新条目必须落入 taxonomy，禁止 orphan 堆一堆 |
| **场景溯源** | `source` 字段记录首次场景，便于回放 |
| **变更日志** | 每次批量更新写 changelog（日期、内容摘要、来源） |
| **冷启动** | 无清单时用内嵌表；任务结束后**创建**清单文件 |

### 3.3 「自动增量」在工程中的实现层次

| 层次 | 自动化程度 | 做法 |
|------|------------|------|
| L0 人工 | 低 | 纠偏后手抄表（当前 Obsidian 流程） |
| L1 半自动 | 中 | LLM 输出【新增标识物】表 → 脚本 parse → PR/append markdown |
| L2 流水线 | 高 | 后处理 API 返回 `new_markers[]` → 写入 SQLite/JSON → 下次注入 prompt |
| L3 在线学习 | 更高 | 用户在 history UI「订正一词」→ 自动成对入库 |

Handy 与 L1–L2 最契合：

- 已有 **history**、**post-process**、**custom_words**  
- 缺的是 **误识对（error→correct）结构** 与 **回写路径**

### 3.4 与 Handy `custom_words` 的关系

| | custom_words（现有） | 标识物清单（范式） |
|--|---------------------|-------------------|
| 结构 | 仅「正确词」列表 | **误识 → 正确** 双端 |
| 匹配 | 模糊（英文偏） | 精确优先 + 可选模糊 |
| 更新 | 用户手填 | 纠偏任务增量 |
| 注入 | Whisper initial_prompt / 模糊替换 | LLM 上下文 + 可选规则替换 |

**推荐双轨：**

1. **规则轨（快、稳）**：高置信 `error→correct` 做精确/正则替换（先于或后于 LLM）  
2. **LLM 轨（懂语境）**：整段纠偏 + 消歧（「数据化」仅在数字化课中改）  
3. **词表轨（custom_words）**：继续服务「希望模型尽量吐出的词」

## 4. 通用流水线（可挂 Handy）

```text
[录音/文件] → ASR (Handy 引擎, 已分片)
      → (可选) 规则替换: markers.verified
      → (可选) filler 过滤
      → LLM 纠偏 prompt:
            + markers 全文/摘要
            + session_context（讲者、主题）
      → 解析输出:
            body → 展示/复制/history
            pending_markers → 待审队列
            verified_new → 合并 markers + changelog
```

**伪接口：**

```rust
struct Marker { asr_error: Vec<String>, correct: String, category: String, ... }

fn load_markers(path) -> Vec<Marker>;
fn apply_rule_corrections(text, markers) -> String;
fn build_correction_prompt(raw, markers, context) -> String;
fn parse_correction_output(llm) -> (body, notes, new_markers);
fn merge_markers(store, new_markers, require_verified: bool);
```

## 5. 从领域文档抽出的「可复用检查清单」

设计/实现 ASR 后处理时自检：

- [ ] 是否有**持久化**误识对照，而不只是写死在 prompt？  
- [ ] 纠偏任务是否**强制加载**该对照？  
- [ ] 输出是否含 **存疑** 与 **新增候选**，可机器解析？  
- [ ] 入库是否区分 **verified / pending**？  
- [ ] 是否有 **changelog**（日期、来源场景）？  
- [ ] 是否禁止 LLM **编造**听不清的内容？  
- [ ] 口语填充词删除是否与「保留讲者风格」平衡？  
- [ ] 编号/数字/百分比是否有**格式规则**（可配置）？  
- [ ] 与 raw ASR、history 是否可对照回放？

## 7. 一句话范式总结

| 范式 | 一句话 |
|------|--------|
| **提示词纠偏** | 硬门禁加载权威词库 + 分层规则 + 结构化输出（正文/存疑/新增），禁止编造。 |
| **易错词增量** | 误识→正确 为原子记录；每次任务产出候选；仅验证后归类入库并记 changelog，使词库随使用自我生长。 |

二者合成闭环：**纠偏消费词库，纠偏反哺词库**——这是领域文档最有工程价值的部分，与具体行业解耦后可直接服务 Handy 及任意垂直 ASR 场景。
