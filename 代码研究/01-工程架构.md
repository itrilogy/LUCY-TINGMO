| 壳 | Tauri 2.x |

## 4. 架构模式

### 4.1 Manager 模式

启动时在 `lib.rs` 注入 `Arc` 状态：

- `ModelManager` — 模型元数据、下载、磁盘路径
- `TranscriptionManager` — 加载引擎、batch/stream 转写
- `AudioRecordingManager` — 麦、录音、VAD 策略
- `HistoryManager` — WAV + SQLite
- `TranscriptionCoordinator` — 生命周期串行化

### 4.2 Command–Event

- **Frontend → Backend**：`#[tauri::command]`（models / audio / history / transcription / settings）
- **Backend → Frontend**：`app.emit` / `tauri_specta::Event`（`model-state-changed`、`StreamTextEvent`、电平、overlay 等）

### 4.3 单实例

第二次启动通过 `tauri_plugin_single_instance` 把 CLI 参数（`--toggle-transcription` 等）发给已运行实例后退出。

### 4.4 单引擎占用

同一时刻只持有一个 `LoadedEngine`；streaming 时把 engine lease 出去，batch 与 stream 互斥。

## 7. 与「引擎管理多 ASR」的关系

Handy 已具备 **引擎门面**：

- 加载：按 `EngineType` 分支
- 推理：统一 `transcribe(Vec<f32>)`
- 流式：统一 `start_stream` / `feed` / `finalize_stream`（仅 cpp streaming 模型）

若做成更清晰的「引擎层」，建议把 **分片策略 / 半实时分段** 放在引擎之上的 **编排层（Orchestrator）**，而不是塞进单个模型实现。
