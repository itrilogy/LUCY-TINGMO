# 05 · 问题分析：长录音内容缩减 / 质量崩坏

## 1. 现象（用户侧）

- 长时间现场录制结束后，转写结果 **大幅变短**、**乱码/重复字**，或整体不可用。  
- 短录音（几秒）正常。  

## 2. 根因总览（按证据强度）

| ID | 根因 | 证据 | 严重度 |
|----|------|------|--------|
| **R1** | 超长 PCM **整段**送入模型，未按 `max_audio` 分片 | 日志 `beyond the ~30 s window`；1808s → 仅 ~1.5k 字 | **P0** |
| **R2** | SenseVoice 训练窗约 **30s**，长音频精度崩 + 内存二次方 | 同一 WARN 文案 + 输出乱码 | **P0** |
| **R3** | 应用层 VAD 只去静音，**不做段级 ASR** | 代码设计；与引擎建议 "Split…with VAD" 未落实 | **P0（相对目标2）** |
| R4 | Stream 非空即采用、跳过 batch | `actions.rs` 逻辑；本机长录用的是 **非 streaming** 模型，本次非主因 | P1 |
| R5 | Stream feed 失败静默 / finalize 30s 超时无回退 | 代码；本机长录未走 stream | P1 |
| R6 | 后处理 LLM 可能改写/压缩 | 本机长录 history `post_process_requested=0`，**本次非主因** | P2 |
| R7 | VAD 阈值导致语音被误删 | 可能放大问题，但 30min 仍有 28.9M samples，主因仍是 R1 | P2 |

## 3. 代码路径：为何「能录满 30 分钟却写不好」

### 3.1 录音侧正常

`AudioRecorder` 把 speech 帧累加到 `processed_samples`，stop 返回完整 `Vec<f32>`。  
日志：`sample count: 28929120` ≈ 1808.07s @ 16kHz — **采集完整**。

### 3.2 转写侧一次吞下

```text
TranscriptionManager::transcribe(audio)
  → session.run(&audio, &run_options)   // 无分片循环
```

无：

- 按秒切分  
- 按 VAD 段切分  
- 读取引擎 `max_audio_ms`  
- 重叠拼接  

### 3.3 引擎明确警告（安装版）

```text
[transcribe_cpp][WARN] sensevoice run: audio is 1808.1 s,
beyond the ~30 s window this model was trained on;
accuracy may degrade and memory use grows quadratically.
Split long audio into <=30 s segments (e.g. with VAD).
See transcribe_capabilities.max_audio_ms.
```

即：**库已提示应用层应分片；Handy 未实现。**

### 3.4 结果对比

| 音频 | 时长 | 输出量级 | 质量 |
|------|------|----------|------|
| 短测 | 2–9 s | 正常一句 | 好 |
| #6 | 1054 s | ~5.8k 字 | 可辨主题，后部糊 |
| #7 | 1808 s | **~1.5k 字** | 严重重复乱码（「标标标」） |

**内容「缩减」本质：** 不是 buffer 被截断，而是 **模型在超窗输入下解码失败/退化**，有效语义崩溃并变短。

## 4. 与「Streaming 优先」逻辑的关系

本机安装版使用的长录模型：

- `SenseVoiceSmall-gguf` → `supports_streaming=false`  
- `Qwen3-ASR-0.6B-gguf` → `supports_streaming=false`  

因此 **长录问题主路径是 batch 不分片**，不是 stream 半成品。  
但若未来改用 streaming 模型做长会议，R4/R5 会成为第二炸弹。

## 5. VAD 角色澄清

当前：

```text
长录音 + vad_enabled
  → 静音帧丢弃
  → speech 拼成「去静音后的长 PCM」
  → 仍可能长达 1800s
  → 一次 ASR
```

目标 2 需要：

```text
VAD 状态机: silence → speech → silence
  on segment_end:
    if segment_dur in [min, max]:
      spawn/queue ASR(segment)
      append text to live buffer
  on stop:
    flush last segment
```

现有 `SmoothedVad` 已有 `in_speech` 状态，可扩展出 `SegmentEvent`，但 **recorder 未上报段边界**。

## 6. 修复方向（详见 07）

1. **P0 强制分片**：`max_audio_ms`（默认 30s）滑窗/VAD 切段 → 循环 `run` → 拼接。  
2. **P0 半实时模式**：段结束即转写，满足目标 2。  
3. **UI 提示**：模型 max 时长、长录音预计时间、超窗警告上浮到用户可见。  
4. **兜底**：分片失败可重试单段；总结果与音频时长做合理性检查。
