# 03 · 关键设计

## 1. 模型 / 引擎管理

### 1.1 EngineType

```text
TranscribeCpp          # GGUF/GGML 统一（arch 运行时探测）
Parakeet | Moonshine | MoonshineStreaming
SenseVoice | GigaAM | Canary | Cohere   # ONNX 路径
```

注意：同一家族可能同时存在 **GGUF（cpp）** 与 **ONNX（rs）** 入口，catalog 决定装载路径。

### 1.2 加载流程

1. 用户选择 `selected_model`  
2. 下载完成 → `TranscriptionManager::load_model`  
3. 按 `engine_type` 构造 `LoadedEngine`  
4. cpp 路径：`Model::load_with` → `session()` → 写回 runtime capabilities  
5. 空闲超时可 unload（`model_unload_timeout`）

### 1.3 能力位（Capabilities）

来自 catalog 预置 + GGUF 元数据运行时覆盖：

- `supports_streaming`
- `supports_translate`
- `supports_language_detect` / `languages`
- （引擎侧还存在 `max_audio_ms` 一类能力；**应用层目前未用它做分片**）

### 1.4 语言处理

- 用户意图：`selected_language`（如 `zh-Hans`）  
- `effective_language_for_model` 按模型能力强制/回退  
- 中文输出可用 OpenCC 做简繁转换

## 2. 录音设计

### 2.1 麦克风模式

| 模式 | 行为 |
|------|------|
| OnDemand（默认） | 开始录时 open stream，结束后 close（或 lazy 30s） |
| AlwaysOn | 常开麦克风，降低首字延迟 |

### 2.2 录音状态机

```text
Idle → Recording{binding_id} → Stopping → Idle
```

### 2.3 采集规格

- 设备原生采样率采集 → `FrameResampler` → **16 kHz mono f32**  
- 帧长 **30 ms**（与 Silero 对齐）  
- Stop 时 drain 到 `EndOfStream`，避免尾部丢帧  

### 2.4 静音边录

`mute_while_recording`：录音时静音系统输出，结束后恢复先前 mute 状态。

---

## 3. VAD 设计

### 3.1 组件

```text
SileroVad（概率阈值默认 0.3）
    ↑
SmoothedVad
  - prefill_frames = 15  (~450ms 起说前回填)
  - onset_frames   = 2   (~60ms 确认起说)
  - hangover offline = 15 (~450ms)
  - hangover streaming = 55 (~1.65s)
```

### 3.2 策略枚举 `VadPolicy`

| 策略 | 何时 | 行为 |
|------|------|------|
| `Disabled` | `vad_enabled=false` | 全帧保留 |
| `Offline` | VAD 开 + 非 streaming 模型 | 静音丢弃，较短 hangover |
| `Streaming` | VAD 开 + streaming 模型 | 静音丢弃，较长 hangover |

### 3.3 当前语义（重要）

VAD 当前是 **帧级门控（keep/drop）**，不是 **段级事件（segment begin/end）**：

- 输出：连续 speech 样本拼接成一个 `Vec<f32>`  
- **不会** 在「一段静音结束后」触发一次独立 ASR  
- 因此 **不等于** 目标 2「VAD 实时分段 + 逐段半实时转写」

## 4. 转写双路径

### 4.1 Batch（默认）

```text
samples: Vec<f32> → TranscriptionManager::transcribe
  → session.run / engine.transcribe*
  → post_process_transcription_text（自定义词 / filler）
```

### 4.2 Streaming（部分 cpp 模型）

```text
start_stream → StreamRouter.open
录音帧 → router.feed → worker stream.feed
stop → finalize_stream → 文本
若无可用 stream 文本 → fallback batch
```

### 4.3 停止时选择逻辑（`actions.rs`）

```text
finalize_stream():
  Ok(Some(非空)) → 用 stream 文本     # 不再 batch
  Ok(空/None)    → batch(samples)
  Err(超时等)    → 失败，无 batch
```

风险：stream 半成品会挡住完整 batch。

### 4.4 Stream 实现细节

- `StreamRouter`：`AtomicBool open` + channel；无 stream 时 feed 几乎零开销  
- Worker 独占 engine lease  
- `STREAM_FINALIZE_REPLY_TIMEOUT = 30s`  
- feed 失败只 `warn`，帧丢弃  

---

## 5. 生命周期协调（Coordinator）

所有 start/stop/cancel 经单线程队列：

- PTT：release 有 50ms grace，抗 X11 键重复  
- Toggle：Idle↔Recording  
- Processing 中忽略新录制  
- `FinishGuard` 在 async 转写结束时通知 coordinator  

---

## 6. 输出与后处理

1. ASR 原始文本  
2. 可选：自定义词模糊匹配  
3. filler / stutter 过滤  
4. 中文 OpenCC  
5. 可选：LLM post-process（DeepSeek 等 OpenAI 兼容）  
6. 剪贴板 + 模拟粘贴（CtrlV / 其它）  
7. 写入 history + 保存 WAV（VAD 后样本）  

---

## 7. 历史与重试

- WAV：`recordings/handy-{unix}.wav`，16kHz mono  
- SQLite：`transcription_history`  
- UI 可对历史条目 `retry_history_entry_transcription`（再跑 batch）  
- `history_limit` + `recording_retention_period` 会清理旧数据

## 9. 设计上的隐含假设（导致长录音问题）

1. **用户录音以短 dictation 为主**（数秒～数十秒），非 10–30 分钟会议。  
2. **引擎内部能处理好任意长度** — 对 SenseVoice **不成立**（~30s 窗）。  
3. **VAD 只是压缩静音，不改变「整段一次推理」**。  
4. **Streaming 最终文本可信任** — 长会话未必。  

目标 1/2 需要打破假设 1–3，引入 **编排层分片 / 段级半实时**。
