## 1. 引言

### 1.1 编写目的

本文档说明「听默」桌面语音成文软件的总体设计、分层架构、核心模块、数据存储、关键接口与安全约束，供软件著作权登记、验收归档及后续维护使用。

### 1.2 软件概述

听默是一款面向个人与实验室场景的 **跨平台本地语音转写（ASR）桌面应用**。用户通过全局快捷键触发录音，系统在本地完成语音活动检测（VAD）、模型推理与文本输出，结果经悬浮层（Overlay）展示，并可写入剪贴板、粘贴至前台应用，或记入历史库供回放与重转写。

软件基于开源项目 Handy 二次开发，采用 **听默 / 鹿溪** 品牌与 LUXI 视觉体系；技术栈为 **Tauri 2（Rust）+ React/TypeScript**。

### 1.3 设计目标

| 目标 | 设计响应 |
| --- | --- |
| 隐私优先 | 默认本机推理；音频不上传实验室服务器 |
| 可扩展引擎 | 统一模型目录与能力抽象，支持多 ASR 后端 |
| 可配置交互 | 快捷键、按住说话、粘贴策略、Overlay 形态可配置 |
| 长音频可用 | 分片 / 短窗适配，避免单次过长输入导致质量崩溃 |
| 可维护 | Manager 分层、命令/事件前后端边界清晰 |

### 1.4 运行环境（设计约束）

| 项目 | 要求 |
| --- | --- |
| 操作系统 | macOS 10.15+；Windows x64；Linux x64 |
| 权限 | 麦克风；macOS 辅助功能（粘贴/部分输入） |
| 硬件 | CPU 可运行轻量模型；GPU/Metal/Vulkan 可加速部分 Whisper 系 |
| 运行时 | 打包为本地应用；开发态需 Rust + Bun |

## 2. 总体设计

### 2.1 逻辑架构

```
┌─────────────────────────────────────────────────────────────┐
│  表现层（React / TypeScript）                                 │
│  主设置窗 · Onboarding · Overlay 窗 · i18n · Zustand 状态    │
└───────────────────────────┬─────────────────────────────────┘
                            │ Tauri Command / Event
┌───────────────────────────▼─────────────────────────────────┐
│  应用壳（Tauri 2）                                            │
│  单实例 · 托盘 · 窗口 · 全局快捷键 · 插件（store/clipboard…）   │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  领域服务层（Rust Managers）                                   │
│  Audio · Model · Transcription · History · Segment Pipeline  │
└───────────┬─────────────────────────────┬───────────────────┘
            │                             │
┌───────────▼───────────┐     ┌───────────▼───────────────────┐
│  音频工具包             │     │  推理后端                        │
│  cpal 采集/设备         │     │  transcribe-cpp / -rs 等        │
│  VAD · 重采样 · 反馈音  │     │  Whisper / Parakeet / …         │
└───────────────────────┘     └─────────────────────────────────┘
            │                             │
            └──────────────┬──────────────┘
                           ▼
              本地持久化：Store · SQLite · 文件
```

### 2.2 物理部署

- **单机桌面进程**：主 UI 窗口 + 可选 Overlay 窗口 + 系统托盘。
- **单实例**：再次启动时将参数交给已运行实例（远程控制开关录音等），避免多开冲突。
- **数据本地化**：设置、历史、录音、模型目录位于用户应用数据目录（标识 `com.pais.handy`）。

### 2.3 技术选型

| 层级 | 选型 | 理由 |
| --- | --- | --- |
| 桌面框架 | Tauri 2 | 小体积、Rust 系统能力、前后端类型化命令 |
| 前端 | React + TS + Tailwind | 设置型 UI 与组件化 |
| 状态 | Zustand + Tauri Store | 前端响应式 + 持久化 |
| 后端 | Rust | 音频实时路径与推理编排性能、安全 |
| ASR | 多引擎适配 | 按模型格式选择 GGML/ONNX 等路径 |
| VAD | Silero ONNX | 轻量端点检测，支撑半实时分段 |

## 3. 模块设计

### 3.1 模块一览

| 模块 | 主要路径 | 职责 |
| --- | --- | --- |
| 应用入口 | `src-tauri/src/lib.rs` · `main.rs` | 初始化、状态注入、命令注册 |
| CLI | `cli.rs` · `signal_handle.rs` | 启动参数与二次实例远程控制 |
| 快捷键 | `shortcut.rs` · `input.rs` | 全局热键与录音触发 |
| 音频管理 | `managers/audio.rs` · `audio_toolkit/` | 设备、录音、电平、反馈音 |
| 模型管理 | `managers/model.rs` · `catalog/` | 目录扫描、下载、加载/卸载 |
| 转写管线 | `managers/transcription.rs` · `segment_pipeline.rs` | 录音→分片→推理→标点→输出 |
| 历史 | `managers/history.rs` · `commands/history.rs` | history.db、重试、标题、保留策略 |
| 标识物/纠偏 | `markers.rs` · `commands/markers.rs` | 易错词与提示词类纠偏数据 |
| 剪贴板 | `clipboard.rs` | 复制与粘贴到前台（竞态处理） |
| Overlay | `overlay.rs` · `src/overlay/` | 录制/结果悬浮窗 |
| 设置 | `settings.rs` · 前端 `settings/*` | 配置读写与 UI |
| 前端壳 | `src/App.tsx` · `components/` | 导航、onboarding、各设置页 |
| 品牌资源 | `src/assets/*` · `src-tauri/icons/*` | Logo、托盘、安装包图标 |

### 3.2 音频与 VAD 子模块

- **设备枚举与选择**：输入麦克风、输出设备、合盖麦克风策略（平台相关）。
- **录音会话**：按快捷键或按住说话进入 Recording 态；缓冲原始 PCM 并重采样至引擎所需采样率。
- **VAD**：Silero 过滤静音；可配置开启半实时：段结束即送 ASR，结果增量上屏。
- **音频反馈**：开始/结束提示音，可自定义。

### 3.3 模型与转写子模块

- **目录与能力**：内置目录 + 用户数据 `models/` + 可选 HF 缓存发现；按模型元数据选择引擎与参数（如最大有效音频时长）。
- **加载策略**：按需加载；可配置空闲卸载超时，降低内存占用。
- **长音频**：按引擎窗口切段（例如部分模型约 30s 有效窗；Qwen3 等按生成预算采用更短切段），拼接展示文本。
- **标点管线（分层）**：
  - L1：停顿启发式（实时段）
  - L2：批量/段级启发式（可扩展 ONNX）
  - L3：可选 LLM 后处理（历史或用户触发）

### 3.4 历史与输出子模块

- **落库**：转写完成写入 SQLite（`history.db`），可选保留录音文件。
- **检索展示**：前端历史页列表、折叠、标题编辑、收藏/删除、限制条数与保留期。
- **重试**：对历史条目用当前模型重新转写或后处理。
- **输出通道**：
  - Overlay 展示（复制 / 粘贴到前台 / 关闭）
  - 系统剪贴板
  - 粘贴到前台（`paste_to_frontmost`：先写后贴、校验，避免旧剪贴板竞态）

### 3.5 表现层设计

- **主窗口**：侧栏导航（通用 / 模型 / 高级 / 后处理 / 历史 / 调试 / 关于）；默认尺寸约 880×640。
- **Onboarding**：首次引导下载/选择模型。
- **Overlay**：独立 WebView 窗口；形态含关闭、药丸、直播等；录制中波形与结果态布局分离。
- **i18n**：全 UI 文案走 i18next；中文品牌文案与多语言 locale。
- **主题**：LUXI 色板 token（鹿溪绿 / 源启白 / 进化蓝 / 深林底）。

### 3.6 品牌与资源设计

| 资源 | 设计说明 |
| --- | --- |
| 应用主 Logo | 鹿溪绿圆角矩形底板；白色声纹弧象征「听」；溪流/路径意象；进化蓝源启点；用于 Dock 与安装包 |
| 实验室 Logo | 鹿溪机构标，关于页圆角展示 |
| 托盘图标 | 空闲 / 录音 / 转写多状态 PNG（含 dark 变体） |

## 4. 核心流程设计

### 4.1 转写主流程

```
用户触发快捷键
  → 校验权限 / 模型已加载
  → 显示 Overlay（若启用）· 托盘状态 Recording
  → 采集音频 · VAD 过滤
  → [可选] 半实时：段完成 → 段 ASR → Overlay 追加
  → 用户停止
  → 剩余缓冲分片 ASR → 合并文本 → 标点
  → [可选] 后处理 LLM
  → 写入历史 · 更新 Overlay 结果态
  → 按 paste 策略：复制 / 粘贴前台 / 仅展示
  → 托盘恢复空闲
```

### 4.2 设置变更流程

前端修改 → 调用 Tauri 命令 / Store 写入 → 后端读设置生效（部分即时，部分下次录音生效）。

### 4.3 单实例远程控制

二次进程解析 CLI（如 `--toggle-transcription`）→ 经 single-instance 插件投递 → 主进程执行与热键等价动作 → 二次进程退出。

## 5. 数据设计

### 5.1 目录布局（用户数据）

```
{app_data}/com.pais.handy/
├── settings_store.json      # 设置
├── history.db               # 历史 SQLite
├── models/                  # 用户模型
└── recordings/              # 录音文件（若保留）
```

另：工程资源内 `resources/models/silero_vad_v4.onnx`；HF 缓存可能位于 `~/.cache/huggingface/`。

### 5.2 主要数据实体（逻辑）

| 实体 | 关键字段（逻辑） | 说明 |
| --- | --- | --- |
| Settings | 快捷键、设备、模型 ID、粘贴方式、Overlay、VAD、语言、后处理等 | JSON Store |
| HistoryEntry | id、时间、时长、文本、标题、模型、音频路径、收藏标记 | SQLite |
| ModelDescriptor | id、名称、路径、引擎类型、能力标签 | 目录/扫描 |
| AsrMarker | 源词、目标词、置信/模式等 | 标识物纠偏库 |

### 5.3 配置与版本

- 应用版本：`tauri.conf.json` / `package.json` / Cargo 版本对齐（V0.9.4）。
- `productName`：听默；`mainBinaryName`：tingmo；`identifier`：com.pais.handy（数据兼容）。

## 6. 接口设计

### 6.1 前后端边界

- **Command（前端→后端）**：如获取/设置麦克风、历史 CRUD、模型状态、复制/粘贴、取消操作等（见 `src-tauri/src/commands/`）。
- **Event（后端→前端）**：录音状态、流式/分段文本、转写完成、错误提示等。
- **类型绑定**：tauri-specta 等生成前端 `bindings`（若启用），减少接口漂移。

### 6.2 对外 CLI 接口

| 参数 | 语义 |
| --- | --- |
| `--toggle-transcription` | 切换录音 |
| `--toggle-post-process` | 切换带后处理的录音 |
| `--cancel` | 取消当前操作 |
| `--start-hidden` | 启动隐藏主窗 |
| `--no-tray` | 无托盘 |
| `--debug` | 详细日志 |

CLI 为运行时覆盖，不写回持久化设置（设计原则）。

### 6.3 外部服务接口（可选）

后处理模块可通过用户配置的 **OpenAI 兼容 HTTP API** 等发送文本；超时、密钥与 Base URL 存于本地设置，不硬编码密钥。

## 7. 安全与可靠性设计

| 方面 | 措施 |
| --- | --- |
| 权限最小化 | 仅申请麦克风与系统辅助相关能力 |
| 密钥 | API Key 存本地 Store，不入库开源默认配置 |
| 单实例 | 避免双写录音与设置 |
| 粘贴可靠性 | 写剪贴板后校验再模拟粘贴，降低竞态 |
| 长音频 | 分片与引擎窗口匹配，截断时尽量保留已生成文本 |
| 更新通道 | Lab 默认关闭自动更新，避免误连上游签发通道 |
| 日志 | 可调级别；调试模式便于取证（不含无意义上传） |

## 9. 约束与扩展性

### 9.1 已知约束

- 部分 Linux/Wayland 环境全局快捷键与粘贴依赖外部工具或合成器行为。
- 模型体积大，首次使用需下载；无网环境需预置模型。
- 二次开发基于 Handy，合并上游需人工解决分叉差异。

### 9.2 扩展点

- 新增 ASR 引擎：扩展 catalog 与 transcription 适配层。
- 标点 L2/L3：替换或增强 `text_punctuate` / 后处理提供方。
- 标识物：导入导出 Markdown，对接实验室词表。
